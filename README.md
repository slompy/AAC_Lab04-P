## Итоговый вопрос

Это не противоречие, потому что Environment.ProcessorCount возвращает количество логических процессоров, а не физических ядер.

## Контрольные вопросы

1. Свойство Environment.ProcessorCount возвращает количество логических процессоров, доступных текущему процессу. Для операционной системы и среды выполнения это число показывает, сколько потоков команд компьютер может обрабатывать параллельно в один момент времени.
2. 
Физическое ядро - это реальный аппаратный вычислительный блок внутри кристалла процессора, который физически выполняет машинные инструкции.

Логический процессор - это виртуальный поток выполнения, который "видит" операционная система. Благодаря технологиям аппаратной многопоточности, одно физическое ядро может разделяться на два логических процессора, чтобы эффективнее загружать свои вычислительные блоки.
3. Один программный поток в каждый момент времени может выполняться только на одном логическом процессоре. Когда программа создает новые потоки, планировщик операционной системы распределяет их по свободным логическим процессорам. В работу включаются простаивавшие ранее вычислительные ресурсы, и общая загрузка CPU закономерно растет.
4. Рост прекращается, когда количество активных вычислительных потоков достигает числа логических процессоров, и загрузка упирается в потолок 90%, в моём случае. В процессоре физически нет лишних блоков для новых потоков, поэтому операционная система ставит их в очередь и начинает по очереди переключать. При большом избытке потоков, процессор даже теряет производительность из-за накладных расходов на постоянное переключение контекста. Кроме того, если потоки не считают, а ждут ответа от диска или сети, загрузка CPU вообще может оставаться низкой.
5. Современные процессоры динамически управляют своей тактовой частотой в зависимости от текущей нагрузки, температуры и энергопотребления:

Энергосбережение. Когда задач мало, процессор сбрасывает частоту и напряжение, чтобы меньше греться, экономить электроэнергию и продлевать время работы от батареи.

Ускорение под нагрузкой - Turbo Boost / Precision Boost. Когда запускается тяжелая задача, процессор кратковременно повышает частоту выше базовой, чтобы быстрее выполнить вычисления.

Защита от перегрева - Троттлинг. Если при длительной максимальной нагрузке температура чипа приближается к критической отметке или превышается лимит мощности, система принудительно снижает частоту для защиты оборудования от повреждения.


## Итоговый вывод

В ходе работы программа с помощью свойства Environment.ProcessorCount определила количество логических процессоров, доступных операционной системе для параллельного выполнения задач. В отличие от физических ядер, логические процессоры представляют собой виртуальные потоки выполнения, создаваемые благодаря технологиям многопоточности, когда одно ядро обрабатывает два потока команд одновременно. Эксперимент с запуском разного числа потоков показал, что загрузка CPU пропорционально растет только до тех пор, пока количество активных потоков не сравняется с числом логических процессоров. При дальнейшем увеличении потоков все вычислительные ресурсы оказываются полностью заняты, загрузка упирается в потолок, а новые потоки просто встают в очередь на выполнение, вызывая лишние накладные расходы на переключение контекста.
